# ADR-0019: Stricter rules adopted with gaps G1 to G21

## Status

Accepted

## Date

2026-10-12 (merged in pull request #31, released in 0.14.0)

## Context

Gaps G1 to G21 came from splitting an edge pairing engine from a cloud core
(`docs/apx-additional-functions/APX-gaps-2026-10-08.md`). A parallel stack
of pull requests (#25 to #29) proposed stricter rules for the same areas.
Pull request #31 combined both and recorded which of these became hard
requirements.

## Decision

- **The change feed is required, with no feature flag.** The change feed
  on APX list routes (Part 5 §5.2 rule 8) adds MUSTs to classes that were
  already optional. The pull request records that the maintainer chose this
  deliberately. No further rationale is recorded.
- **The issuance gates in §19.4 are MUSTs.** A violation cannot be issued
  on match evidence that is lenient or not applied, or on an evidence read
  that is pending or rejected (Part 19 §19.4).
- **Exit-only Sessions are excluded from occupancy** as a MUST.
- **Violation imports have their own route**,
  `POST /v1/enforcement/violation-imports` (Part 19 §19.2), with the
  `ViolationImport` and `ViolationAppliedPayment` schemas.
- **The change feed uses optional envelope members** (`updateMode`,
  `cursor`, `deleted`, `grantAdditions`, `next`) rather than a `oneOf`.

## Consequences

- Implementations of the affected classes must serve the change feed
  before they can claim them.
- Enforcement cannot issue on match evidence or reads that have not been
  applied or reviewed.
- The change was checked as additive by oasdiff against the previous
  bundle.
